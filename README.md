# 芸能労災 投稿デスク

@entame_rosai（X／Instagram）の投稿案を、**そのままコピペして投稿するための一覧**。
直近10日分が並びます。

公開URL： https://yabemasaru23-source.github.io/entame-rosai-posts/

---

## 投稿する人へ

1. カードの「本文をコピー」を押す
2. X / Instagram の投稿画面に **そのまま貼る**（書き足さない・削らない）
3. 画像があるカードは画像を保存して添付し、**代替テキスト（ALT）も必ず入れる**
4. 投稿したら、そのカードの欄に **投稿のURLと自分の名前を入れて「保存」**
5. 最後に画面下の **「まとめて報告」** を押し、出てきた文面を矢部さんに送る

### 保存した記録はどこにあるか

**その端末のブラウザの中だけ**です（`localStorage`）。静的サイトなので、
他の人の画面や矢部さんの手元には自動では届きません。
**だから最後に「まとめて報告」で送る**、という形にしています。

- URLは形を見ています。X のカードに Instagram のURL、プロフィールのURL（`/status/` が無い）は弾きます
- 間違えたら「取り消す」で消せます
- すでに台帳に記録ずみの投稿は「投稿済み（記録ずみ）」と出て、欄は出ません

**1日2投稿まで。** 数分以内の連続投稿はしない（スパム判定を受けます）。
本文を直したくなったら、投稿せずに確認してください。
X は投稿後に本文を編集できず、直すには削除→再投稿しかありません（表示回数が0に戻ります）。

「機械チェック：そのまま投稿しないでください」と赤く出ているカードは投稿しない。

## 更新する人へ（矢部さん／AI）

毎日、成果物を作ったあとに1回：

```
python 投稿サイト/build.py
```

`output/YYYY-MM-DD/` の直近10日分を読み、`index.html` と `assets/` を作り直します。
そのあと push すると GitHub Pages に反映されます。

```
cd 投稿サイト
git add -A
git commit -m "投稿デスク更新 YYYY-MM-DD"
git push
```

### 何を読んでいるか

| サイトの表示 | 読んでいるファイル | 本文の範囲 |
|---|---|---|
| X（@entame_rosai） | `output/<日付>/x_post.txt` | 先頭から、区切り線／見出し行の手前まで |
| X（@yabemasaru23） | `output/<日付>/x_post_yabemasaru23.txt` | 同上 |
| Instagram | `output/<日付>/instagram_post.md` | 「## キャプション」以降、次の見出しまで |
| 状態・投稿URL | `output/posting_log.md` | 日付×媒体で引き当て |
| 画像 | `output/<日付>/x_image/` `instagram/` ほか | `assets/` に複製 |

**成果物ファイルは本文をいちばん上に書く**という決まりに乗っています（`SKILL.md` 8-1）。
前書きを付けると、それが本文として表示されます。

### 機械チェック

`tools/rules.py` をそのまま呼んでいます。禁止語のリストはこのサイト側に持ちません
（持つと `memory/feedback_compliance.md` とずれるため）。

- 赤（要修正）… 禁止文字列・禁止表現・競合名・絵文字・内部ラベル
- 黄（要確認）… 競合の調査由来かもしれない数字（`0.3%` は保険料率と同じ表記のため必ず出ます）

### 報告が届いたら（矢部さん／AI）

送られてきた文面の投稿URLを `output/posting_log.md` に転記し、
`python tools/check_published.py <URL> --against output/<日付>/x_post.txt` で
**案と公開された本文が一致しているかを照合する**（2026-09-12 の事故の再発防止）。

## このサイトでできないこと

- **投稿はできません。** 下書きを渡すだけの台です。公開ボタンは人が押します
- **保存した記録は共有されません。** 端末をまたぐと消えます（別のPC・スマホでは見えない）
